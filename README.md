# hawthornhwb.github.io
Personal blog powered by GitHub Pages

## 内容维护

- 技术文章放在 `_posts/`，首页「文章」栏目展示。
- 生活日记放在 `_life/`，首页「生活」栏目按日期倒序展示，两栏共用列表样式。每篇日记使用独立的 `/life/文件名/` 地址、文章排版和每日阅读量，返回链接指向生活栏目。
- 新增日记时创建 Markdown 文件，在头部填写 `title`、`date`（如 `2026-09-26 00:00:00 +0800`）和 `description`，正文写在头部的 `---` 之后。布局和「生活」分类由 `_config.yml` 自动设置。
- 自我介绍在 `about.html`，通过顶部导航「关于」进入。

## 每日访问量

- 首页显示「首页今日访问」，每篇文章显示「本文今日阅读」。这是当前页面的浏览次数（PV），刷新也计数，不是独立访客数。
- 按 `Asia/Shanghai`（北京时间）划分日期，各页面独立计数，从功能上线后开始积累，无法补回历史访问。页面标注本次加载时的统计日期，跨午夜后刷新查看新一天的数据。
- 使用[杜老师说 BSZ](https://bsz.dusays.com/) 的公共统计服务，无需密钥或额外服务器。只在正式域名 `hawthornhwb.github.io` 下发送计数请求，本地预览不计数。
- 为降低首次访问的接口等待，统计源由 `busuanzi.cc` 切换为 `bsz.dusays.com:9001`。发布切换后重新累计，旧服务的数据不迁移、不删除；旧浏览器缓存也不用于新服务，避免先显示旧数字再跳回新计数。仍按北京时间每日、每页独立统计。
- 适配器位于 `_includes/daily-views.js`，沿用[平台官方脚本](https://jsd.dusays.com/npm/penndu@17.0.0/bsz.js)的 POST 协议，向 `https://bsz.dusays.com:9001/api` 发送一次请求。以 `https://hawthornhwb.github.io/__daily_views__/YYYY-MM-DD/原页面路径` 作为 `x-bsz-referer` 请求头，校验 `success: true` 后读取 `data.page_pv`，从而实现单页每日统计；这个路径不需要实际生成网页。日期之间相互独立，URL 查询参数和锚点不影响计数。浏览器首次跨域请求可能先发送 OPTIONS 预检，预检不计数。
- 统计脚本直接嵌入 `<head>`，在样式表和正文加载之前发起异步请求，省去单独下载统计脚本的等待。不会阻塞正文显示。
- 计数节点解析完成后立即展示已就绪的缓存或接口结果，不等待 `DOMContentLoaded`，避免页面末尾的主题脚本等延迟数字显示；`DOMContentLoaded` 仅作为展示兜底，不会再次发起计数请求。
- 同一浏览器再次访问时，优先显示 `localStorage` 中当天该页面最近一次成功读取的数字，并标注「上次记录，更新中」；后台完成计数后替换为最新值。缓存不会代替上报，每次加载仍只发起一次计数请求。跨天不复用旧数字，禁用存储时正常请求接口。首次访问直接请求新服务，实际速度仍受访客网络和公共服务状态影响。
- 仅向服务发送公开域名与日期化页面路径，不发送查询参数、来源页或 Cookie。服务端仍能看到请求 IP；数据保存在第三方，公共计数仅供大致参考，可能受拦截器、服务中断或人为请求影响。
- 请求超时或响应异常时，无缓存显示「暂不可用」，有缓存保留数字并标注「上次记录，更新暂不可用」，不伪造为 0，也不自动重试以免重复计数。未启用 JavaScript 时显示「—」。公共接口若发生变更，需要更新适配器。
- 当前显示当日计数，不包含历史趋势图、后台报表或文章列表中各篇文章的批量计数。

验证统计逻辑：`node --test tests/daily-views.test.cjs`。
